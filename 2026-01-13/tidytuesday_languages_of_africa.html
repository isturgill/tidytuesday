1 Introduction

From TidyTuesday:

This week we’re exploring data about popular languages spoken on the African continent. The dataset this week comes from the Languages of Africa page on Wikipedia.

The number of languages natively spoken in Africa is variously estimated (depending on the delineation of language vs. dialect) at between 1,250 and 2,100 and by some counts at over 3,000.

The dataset is rich with information on the number of languages spoken across the continent. Some of the questions that could be thought of include:

  • Which country in Africa has the largest number of spoken languages?

  • Which family of languages has the highest density of speakers?

  • Are there any languages that cut across multiple countries?

Can’t wait to see the kind of visualisations that can be created!

Thank you to Robert Muwanga, Data Enthusiast for curating this week’s dataset.

2.3 Data scraping

We are given two sources of data to use that will need to be scraped and cleaned. Let’s go through them one at a time so we can understand what data we’re pulling. Our eventual goal is to create a link between a list (or vector) of countries in Africa and data that contains: (1) which language belongs to which language family, (2) how many estimated native speakers there are for each language, and (3) which language(s) are spoken in which countries.

Indeed, we get a list of tibbles of size 2, as expected. The second tibble includes “dependencies or other territories,” so we’ll focus on the first tibble, which includes just formal countries. The author also has specific domain (geography) knowledge to recognize that there’s a small discrepancy between the datasets we’ll be using. From worldometers to wikipedia, we have Côte d'Ivoire = Ivory Coast and Cabo Verde = Cape Verde. Rather than change the names directly, the author elected to add the two additional names to the country list. # The list of tibbles is not named, so we pluck the first one by index

  pluck(1) |>
  pull("Country") |>
  append(c("Ivory Coast", "Cape Verde"))

2.4 Data cleaning

The author suggests some cleaning to make the data easier to work with. Here, we’ll remove extraneous information after " " whitespaces in the columns and convert the native_speakers column to an integer format. Overall, we’ll make a simplification and a major assumption about the native_speakers:

2.4.0.1 Assumptions

  1. Any numeric range will be converted to just the first number in the range (e.g., the minimum value).
  2. Where multiple countries are listed in country for a language, the same number of native_speakers is assigned to each country. This will double-count individuals for some questions we may want to ask, but we have no idea what proportion should be assigned to each. Alternatives may include dividing the number equally among all countries, or if you had the population sizes of each country, weighting estimates by the country populations. Here for simplicity and to follow the data given, we’ll leave it as-is.
# For country, we first concatenate all the african_countries
# with a "|" delimiter, which we'll use as a regex "OR" search pattern to extract
country_regex <- str_c(african_countries, collapse = "|")

# Here we grab the first substring separated by whitespace for family and 
# native_speakers and then apply the country extraction, removing missing data
dat <- african_languages |>
  mutate(family = str_split_i(family, " ", 1),
         native_speakers = str_split_i(native_speakers, " ", 1),
         country = str_extract_all(country, country_regex)) |>
  unnest(country) |>
  filter(country != "" & !is.na(country))

# Lastly, let's convert native_speakers to a numeric column
# Let's also remove any introduced NA's and any duplicate rows
dat <- dat |>
  mutate(native_speakers = parse_number(native_speakers)) |>
  drop_na() |>
  distinct()

3 Analysis

Now, with our cleaned (though not perfect - see Section 2.4.0.1 above), we are ready to perform some simple analyses to answer the questions asked in the Section 1.

# We'll first show the summary table and then actually plot it

  group_by(country) |>

  slice(1:10) |>

Here we can see that Cameroon appears to be the country with the most languages spoken (exactly 100!). Next is Congo at 80, then Nigeria at 74 to round out the top 3. We can also try to plot these data on a map of Africa, though it’s not perfect; there are some country naming discrepancies that would take extra time to resolve. If this was for a formal analysis or publication, you may wish to take the extra time to resolve these discrepancies.

# Get base world map data
world_map <- map_data("world")

# Process as before, but we'll need to adjust the Congo's name for the map database

3.2 Family of language with the most speakers

Next, let’s look at which family of languages appears to have the most speakers. We know our data are flawed as noted in Section 2.4.0.1, so we’ll incorrectly over-count. However, without knowing how to appropriately assign proportions to each country, the best we can do is either not attempt to ask this question until we can resolve that issue (probably for the best), or give an answer with an asterisk. Here, let’s give the top 5 with the data we have.

# Top 5 - first show the table and then plot as before
dat |> 
  group_by(family) |> 
  summarize(num_speakers = sum(native_speakers)) |> 
  arrange(desc(num_speakers)) |>
  slice(1:5)
family num_speakers
Afroasiatic 2266358060
Niger–Congo 1214260335
Nilo-Saharan 111091000
Indo-European 101665300
Austronesian 18000000 
dat |> 
  group_by(family) |> 
  summarize(num_speakers = sum(native_speakers)) |> 
  slice(1:5) |> 
  ggplot(aes(x = reorder(family, -num_speakers), 
             y = num_speakers,
             fill = family)) + 
  geom_col() + 
  scale_y_log10() +
  labs(title = "Top 5 language families spoken in Africa (*overcounted)",
       subtitle = str_c("TidyTuesday: ", github),
       x = NULL,
       y = "Number of speakers (log10-scale, *overcounted)") +
  guides(fill = "none") + 
  scale_fill_npg() +
  theme_bw()

Note that we’re now in the log10-scale for the y-axis because of the massive differences in estimated numbers of speakers across language families. Also note another issue with the dataset that we didn’t catch earlier in the data cleaning: there are actually two families that should be merged: Afroasiatic = Afro-Asiatic. Normally we’d just have to spend time looking closely at the data to notice data entry and tidying errors like this, or see them downstream in the results as we have now. If you wanted to correct this, you could first confirm that they are indeed identical categories that should be merged, and then run:

dat <- dat |> 
  mutate(family = str_replace(family, "Afro-Asiatic", "Afroasiatic"))

And then you’d want to re-run any analyses that you had performed, this time using the corrected data.
